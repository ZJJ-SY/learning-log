## 学到的东西

### 1. GitHub 靠「邮箱」把提交关联到账号
- **问题**：`git config` 里的 `user.name` / `user.email` 到底影响什么？
- **结论**：GitHub 用 **commit 里的邮箱**去匹配账号。邮箱不对，这个提交就不算你的——
  **主页贡献图不会亮，活动统计也不计**。而贡献图恰恰是坚持写日志最大的正反馈。
- **坑**：我的 `user.email` 一开始写成 `junjiezhou671.@gamil.com`，两个错误：
  域名 `gamil` 拼错、`@` 前多了一个点。**而 `git config --list` 只检查格式合法性，
  不会告诉你邮箱是不是你账号绑定的那个——这种错误必须自己知道原理才能发现。**

### 2. 引号没闭合会把换行和后面的命令一起吞进配置值
- **问题**：`git config --global --list` 里多出一行莫名奇妙的 `git config --global user.name`
- **结论**：打开 `~/.gitconfig` 才发现，`user.name` 的真实值是
  `"ZJJ-SY\ngit config --global user.name "`——之前某次命令引号没配对，
  换行和后续文字全被当成了值的一部分。
- **教训**：配置文件出问题时，**直接打开文件看原文**，比反复敲 `--list` 有用。
  `--list` 会把多行值显示成多行，看起来像两条独立配置，很有迷惑性。

### 3. Git 只跟踪文件，不跟踪空目录
- **问题**：建了 `notes/`、`ctf/` 却推不上去
- **结论**：Git 的版本控制单位是**文件**。空目录放一个 `.gitkeep` 占位（文件名任意，
  只是社区惯例）。

### 4. 认证只在 push 时需要，clone 公开仓库不用
- **结论**：`git clone` 一个 public 仓库**完全不需要身份认证**，所以刚才一路顺畅。
  但 `git push` 必须验证身份，GitHub 早已不支持账号密码，要用
  **Personal Access Token** 或 **SSH 密钥**（我用的是 Git Credential Manager 浏览器授权）。

## 遇到的问题 / 卡住的地方
- 邮箱拼写错误 → 自己核对 GitHub 账号绑定的邮箱后改掉
- `user.name` 值里混进换行 → 打开 `.gitconfig` 看原文才发现，重新设置一次即可
- 空目录推不上去 → 加 `.gitkeep`
